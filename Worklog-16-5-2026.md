# Worklog 16-5-2026

## Date / time

2026-05-16 (shipping wrap-up commit).

## Context

Follow-up to v0.1.5: smoke logs showed scheduler/check activity but no Discovery traces operator confusion; HTTP routers returning **401** without upgraded JSON expectations; request for router **credentials** support where Basic auth applies.

## Why this work was done

- Prove Discovery runs end-to-end (command binding + service + correlatable logs).
- Reduce wrong-subnet/user-error pain via visible **detected IPv4 networks** from OS adapters.
- Let monitors authenticate to endpoints that use **HTTP Basic** (many SOHO gateways).
- Align newly added targets’ HTTP checks with common gateway behaviour (**401/403** acceptable).

## What changed

- Shipped **v0.1.6** (`Directory.Build.props`, `VERSION`, `README`, `CHANGELOG`).
- `DiscoveryService`: inject logger; scan/sub-scan lifecycle logs; per reachable host line; multi-subnet summary.
- `DetectedIpv4Network` / `GetDetectedIpv4Networks()` with NIC description.
- Desktop Discovery UI: clickable adapter+CIDR rows, refresh list; VM logs UI discovery intent/CIDR selection.
- `HttpCheckParams`: `Username`, `Password`; executor builds Basic header; smarter 401/403 DOWN hints.
- New target HTTP default `ExpectedStatuses`=`200-399,401,403`; docs (`docs/index.md`) expanded for Discovery logs + Basic auth limitations.

## Where changes were made

- `src/NextWatch.Core/Services/DiscoveryService.cs`
- `src/NextWatch.Core/Checks/CheckParameters.cs`, `HttpCheckExecutor.cs`
- `src/NextWatch.Desktop/MainWindow.xaml`, `ViewModels/MainViewModel.cs`
- `tests/NextWatch.Core.Tests/HttpExpectedStatusesTests.cs`
- `docs/index.md`, `docs/architecture.md`

## How it was implemented

- **Discovery logging:** `ILogger<DiscoveryService>` primary ctor DI; `ScanSubnetAsync` / `ScanConnectedNetworksAsync` emit bounded INFO lines (per-hit adds ICMP-visible hosts only).
- **Detected networks:** single-pass NIC enumeration; `TryAdd` CIDR keeps first interface label.
- **Basic auth:** per-request `HttpRequestMessage` + `AuthenticationHeaderValue` (shared named HttpClient remains safe—no handler-global credentials).
- **Exports:** existing sanitizer removes lowercase `password` keys — router passwords omitted from exported JSON.

## Tests run

- `dotnet test tests/NextWatch.Core.Tests/NextWatch.Core.Tests.csproj -c Release` — **25 passed**.
- `dotnet build src/NextWatch.Desktop/NextWatch.Desktop.csproj -c Release` — succeeded.

## Known risks / follow-ups

- Per-host Discovery INFO can flood Logs/grid on dense subnets (still capped by UI trim max probes default **64** in Desktop discovery commands).
- **Digest**/HTML-login routers still unsupported beyond loosening `ExpectedStatuses` or Ping/TCP.
- Existing HTTP checks in DB keep legacy JSON until edited/imported—operators may still see **401 outside expected set** until parameters updated.

# Worklog 16-5-2026 — Slice 2

## Date / time

2026-05-16 (later in day, UI/UX redesign + README polish).

## Context

Two follow-ups after v0.1.6 ship:

1. README didn't follow the standard GitHub layout (no badges row, no TOC, no screenshots placeholder, weak install/usage split).
2. Desktop UI looked unfinished — generic WPF chrome, monolithic Settings row, plain-text status, no visual hierarchy.

## Why this work was done

- Make the GitHub landing page match conventions newcomers expect (build/license/.NET/platform badges, blockquote tagline, manual TOC, Screenshots section, Installation vs Usage split, Issues link).
- Replace the default WPF look with a coherent design system so the app feels like a finished product, not a prototype. Status should be **scannable at a glance** (KPIs + colored pills), not a buried text token.
- Keep all existing bindings/commands intact so the redesign is XAML-only with **zero behavior regressions**.

## How it was implemented

- **Tokens, not magic numbers**: every brush is a named `Brush.*` resource — surface, border, accent, semantic, semantic-soft. Keeps future themes / contrast tweaks single-source.
- **Implicit styles** for `Button`, `TextBox`, `ComboBox`, `CheckBox`, `DataGrid` so existing markup picks up the new look without per-control styling.
- **Variant button styles** (`Btn.Accent`, `Btn.Subtle`, `Btn.Ghost`, `Btn.Danger`) for visual hierarchy.
- **Sidebar nav** via custom `TabControl` template with `TabStripPlacement="Left"`, branded header, and a `TabPanel` for items styled as nav pills (rounded, hover, selected = accent soft + accent text).
- **Status pill** rendered via `StatusToBackgroundConverter` + `StatusToForegroundConverter` resolving brushes from the app dictionary at convert time → no view-side colors.
- **Log level coloring** via `LogLevelToForegroundConverter` (`ERR/FTL→Down`, `WRN→Warn`, `INF→Accent`, others muted).
- **Bindings preserved**: every command (`RefreshCommand`, `AddTargetCommand`, `RunDiscoveryCommand`, `ApplyDetectedNetworkCommand`, `Clear/Copy/Open` log commands, `SaveLanSettingsCommand`, `Export*`, `CheckForUpdatesCommand`) and every collection (`Targets`, `Tags`, `RecentAlerts`, `LogLines`, `DetectedNetworks`) is reused exactly.
